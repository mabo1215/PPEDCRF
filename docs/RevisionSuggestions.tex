\subsection*{Finding G1 (Critical): double-blind anonymity violation via a self-identifying checkpoint repository name}
\label{sec:g1}
The manuscript is submitted under acmart's \texttt{anonymous} review mode
(\texttt{documentclass[manuscript,screen,review,anonymous]\{acmart\}}), and
all author, affiliation, and contact information is correctly commented out
in both \texttt{main.tex} and \texttt{appendix.tex}. However, the
\emph{rendered} text of both files named an actual, identifiable Hugging
Face account: \texttt{main.tex} (Reproducibility audit paragraph) and
\texttt{appendix.tex} (E5 diagnostic section) both referred to ``the public
\texttt{mabo1215/ppedcrf-sensnet} checkpoint.'' This is not a commented-out
line; it compiles into the PDF exactly as written. An ACM TOMM editor or
reviewer performing even a cursory anonymity check (e.g., searching the PDF
or pasting suspicious tokens into a search engine) could de-anonymize the
submission from this single username, which is a plausible desk-reject or
editorial-flag condition for a venue that enforces double-blind review. This
is the same category of leak that double-blind checklists specifically ask
authors to self-audit (code repository names, dataset hosting account names,
model hub usernames), and it is exactly the kind of leak that survives
casual proofreading because the surrounding sentence reads naturally.

\textbf{Required action and resolution.} Both occurrences were replaced with
venue-neutral phrasing that preserves the scientific content of the claim
(that a second, independently hosted copy of the checkpoint was audited and
found bit-identical to the local one) without naming the hosting account:
``the publicly hosted checkpoint released alongside this submission
(repository name withheld for double-blind review).'' No other occurrences
of author names, affiliations, institutional emails, or identifiable GitHub
usernames were found in the rendered text of either file; the only other
matches (in \texttt{main.tex}'s commented-out \texttt{Code:} line and in
\texttt{paper/backup/main\_010324.tex}, an inactive backup file not included
in the build) do not compile into the submitted PDF.

\textbf{Completion gate.} Satisfied. \texttt{grep} over the rendered text of
\texttt{paper/main.tex} and \texttt{paper/appendix.tex} for the account name,
common author names, and institutional affiliations returns no remaining
matches, and both files rebuild cleanly.

\subsection*{Finding G2 (Moderate): arithmetic error in the Gaussian-mechanism calibration example}
\label{sec:g2}
Section~3.2 (``NCP Control and DP-Style Calibration'') fixes
$\delta=10^{-5}$ and states $\sqrt{2\log(1.25/\delta)}\approx 4.73$, then
uses this to claim that $\sigma_0=8$ corresponds to
$(\varepsilon,\delta)\approx(0.59,10^{-5})$. Recomputing the stated
expression with $\delta=10^{-5}$ gives
$\sqrt{2\ln(1.25/10^{-5})}=\sqrt{2\ln(125000)}=\sqrt{2\times 11.736}=\sqrt{23.472}\approx 4.845$,
not 4.73; with the clipping bound $C=1$ as described in the same paragraph,
this gives $\varepsilon\approx 4.845/8\approx 0.606$, not 0.59. The error is
self-contained (the derived $\varepsilon$ is internally consistent with the
paper's own, incorrect, 4.73 constant, so it is not visible from the
surrounding text alone), but a reviewer with a differential-privacy
background who recomputes the one worked example the paper provides for its
central calibration rule would find it wrong, which undermines confidence in
Eq.~(5) even though the equation itself is written correctly. This is a
pure arithmetic slip, not a methodological problem, and needs no new
experiment to fix.

\textbf{Required action and resolution.} Recomputed the constant precisely
($\sqrt{2\log(1.25/10^{-5})}=4.8448\ldots$) and corrected both numbers in
Section~3.2: the constant is now reported as $\approx 4.84$ and the derived
operating point as $(\varepsilon,\delta)\approx(0.61,10^{-5})$. No other
Gaussian-mechanism arithmetic (the PSNR--MSE conversions in
Table~\texttt{tab:matched\_psnr}, or the 5.97\,dB PSNR-gap statement in
Section~4.4) uses this constant, so no other passage required a matching
correction.

\textbf{Completion gate.} Satisfied. Section~3.2 now reports $\approx 4.84$
and $(\varepsilon,\delta)\approx(0.61,10^{-5})$, and \texttt{paper/main.tex}
rebuilds with 0 LaTeX errors.
