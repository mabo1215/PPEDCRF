\subsection*{Overall Assessment}
The manuscript is unusually candid: nearly every quantitative claim carries
an explicit scope qualification, and the paper's own Appendix
(Section~A, ``Matched-PSNR/Effective-MSE Comparison'') already runs a
descriptive fairness check of the kind the original reviewers demanded. That
candor is a strength. But reading the manuscript fresh, as a new reviewer,
surfaces two issues that the manuscript initially stated too strongly without
the statistical apparatus to support the claim, plus one process gap that this
fresh-review pass ran into directly. The current pass closes the first two with
real outputs and a bounded interpretation; the remaining item is a
provenance-documentation gap.

\subsection*{Finding F1 (Major): the matched-PSNR null result required a paired test}
\label{sec:f1}
Appendix Table~\texttt{tab:matched\_psnr} and the surrounding text now avoid
the stronger phrase ``statistically indistinguishable'' and instead report
identical displayed Top-1 point estimates for six sigma-tunable variants
(\texttt{full}, \texttt{no\_temporal}, \texttt{no\_ncp}, \texttt{unary\_only},
\texttt{no\_dcrf}, \texttt{global\_noise}) at the three targets. This is an
appropriate descriptive correction, but it is not a statistical test of
equivalence. The underlying sample is only 12 paired locations $\times$ 3
seeds $=$ 36 paired binary retrieval outcomes per cell, restricted to one
backbone (ResNet18) and one gallery size (48). The real follow-up analysis now
reports zero discordant pairs, exact McNemar $p=1.0$, and a query-cluster
bootstrap 95\% CI of $[0.000,0.000]$ for all 15 variant--target comparisons;
the smallest significant asymmetry at $n=36$ is six discordant pairs. This
matters because this
comparison is the load-bearing evidence for the paper's central
repositioning: that PPEDCRF's contribution is better quality at matched
privacy rather than more privacy at matched quality. A claim that important
should rest on a real paired test and an explicit statement of how much power
that test had at this sample size, not on rounding alone.

\textbf{Required action and resolution.} We ran the newly added
\texttt{src/scripts/significance\_test\_matched\_psnr.py} (paired McNemar
exact test plus a query-level cluster bootstrap CI) against the real
12-point sigma sweep. For every matched-PSNR target and each of the five
variants compared against \texttt{global\_noise}, the exact $p$-value is 1.0,
the bootstrap 95\% CI is $[0.000,0.000]$, and there are zero discordant pairs;
the minimum significant asymmetry is six of 36 pairs. These results are now
reported in Appendix~A and the main-text/Conclusion wording has been updated
to describe a non-rejection result rather than equivalence. The analysis
remains restricted to one backbone/gallery cell, as specified by the original
completion gate.

\textbf{Completion gate.} Satisfied. A regenerated
\texttt{matched\_psnr\_significance.csv} exists with McNemar $p$-values and
bootstrap CIs for every
(\texttt{target\_psnr}, variant) pair currently in Table~\texttt{tab:matched\_psnr}
and is written back into the appendix table or its surrounding text; the
main-text and Conclusion wording is updated to match the tested claim rather
than the rounded point estimate.

\subsection*{Finding F2 (Moderate): the current pipeline's own run-to-run determinism is verified}
\label{sec:f2}
Appendix Section~``MixVPR Margin Diagnosis and Mitigation Status'' reports
that the current proxy50 run no longer reproduces an adverse MixVPR transfer
result the reviewers cited, and states plainly that no preserved copy of the
earlier run exists to identify why. That is an honest account of a run that
already happened, but it leaves a more basic and directly answerable question
unaddressed: is the \emph{current} code, given its fixed seeds
$\{1234,1235,1236\}$ and current checkpoint, even deterministic from one
execution to the next? If it is, the earlier discrepancy is confidently
attributable to a prior code or checkpoint change rather than to
non-reproducibility of the present numbers, which is a materially stronger
statement to be able to make about every other result in the paper. If it is
not, that is itself an important, currently undocumented limitation that
would affect the credibility of every seed-averaged table in the manuscript,
not just the MixVPR cell.

\textbf{Required action and resolution.} We ran the newly added
\texttt{src/scripts/check\_run\_determinism.py} on two independent real-GPU
MixVPR proxy50 executions using the same code tree, checkpoint, gallery
construction, and seeds. The checker found exact agreement within
$\mathrm{rtol}=10^{-6}$ and $\mathrm{atol}=10^{-9}$ for all 3,750 rows and 20
columns. The appendix now attributes the earlier discrepancy to a prior code
or checkpoint state rather than current run-to-run nondeterminism, while
acknowledging that the earlier state itself is unavailable.

\textbf{Completion gate.} Satisfied. A determinism-check run (real GPU
execution, not a schema smoke test) produced two independent output directories for
at least the MixVPR proxy50 cell, \texttt{check\_run\_determinism.py} has been
run against them, and its outcome (pass or a named mismatch) is stated in the
appendix.

\subsection*{Finding F3 (Editorial, no experiment required): paper-facing CSVs are not provenance-checked across machines}
\label{sec:f3}
This review pass discovered, while trying to verify the two findings above
against the manuscript's backing data, that \texttt{src/outputs/} is
git-ignored and that the paper-facing runs were stored on a different machine.
The F1 sigma sweep and F2 duplicate runs have now been pulled from the vGPU
machine and independently hashed. The older proxy12/proxy50 and E4 outputs
remain remote-only but have captured remote SHA-256 values. The E1 MSLS and
E5 KITTI-360 manifest/export files are not present in the reachable output
tree, so their provenance cannot honestly be completed in this pass. This is
not a defect in the manuscript, but it was a real gap in the revision
process: without a lightweight, versioned record of exactly which run (by
checksum) produced each paper-facing number, a future session on a different
machine could not verify a table without re-obtaining the full multi-gigabyte
output tree. The new record closes that gap for every reachable export.

\textbf{Required action and partial resolution.} The new
\texttt{docs/experiment\_provenance.md} records the remote code revision,
source-file hashes, and SHA-256 values for every currently reachable
proxy12/proxy50, E2, F1, F2, and E4 CSV/JSON export; local copies of F1 and F2
are checked against the remote hashes. The same record names the E1 MSLS and
E5 KITTI-360 exports as unavailable rather than inventing checksums. This is
therefore a partial completion pending those two missing export trees.

The original required action was to add a short provenance table to
\texttt{docs/experiment\_progress.tex} (or a new
\texttt{docs/experiment\_provenance.md}) recording, for every CSV or JSON
export currently cited by a paper table (proxy12, proxy50, the E1 MSLS
manifests, the E2 sigma-sweep directories, the E4 utility manifests, the E5
KITTI-360 diagnostic), its output path, the code revision (git commit SHA)
that produced it, and a SHA-256 checksum of the file. This is a documentation
task, not a new experiment, and can be completed on whichever machine
currently holds each output tree.

\textbf{Completion gate.} Partially satisfied. The provenance table exists
and covers every reachable paper-facing export, but the gate remains open
until the missing E1 MSLS and E5 KITTI-360 export files are restored and
hashed.
