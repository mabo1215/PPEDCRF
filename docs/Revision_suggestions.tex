\section*{Independent Review --- ACM TOMM Revision Cycle (2026-08-31)}

\subsection*{Overall Assessment}
The manuscript is internally consistent for the current fixed-budget
proxy12/proxy50 retrieval study and the corrected E4 segmentation evaluation.
However, the response-letter requests concerning true geographic place labels
and independent validation of the learned unary map are still open. A new
public-data search identifies a concrete path for both items, but registration,
download, manifest construction, and GPU execution must precede any numerical
writeback to the paper.

\textbf{Recommendation:} Major revision for evidence completion, followed by a
new audit after the public-data runs. The current proxy results must remain
explicitly scoped as paired-scene retrieval evidence.

\subsection*{Current Evidence That Is Already Adequate}
\begin{itemize}
    \item The released implementation now defines the sigmoid, average-pooling
    smoother, kernel, stride, padding, mean-field iterations, and temporal
    reuse. The unary architecture and checkpoint provenance are also documented.
    \item The proxy12 and proxy50 retrieval tables use the current CSV exports,
    and the manuscript qualifies transfer as attacker-dependent. The fixed
    \(\sigma_0=8\) comparison is no longer described as a matched-privacy
    advantage.
    \item E4 segmentation uses indexed VOC targets, the official DeepLabV3
    preprocessing, nearest-neighbour target resizing, and restored output
    logits. The CUDA mIoU result is integrated in the main paper.
    \item Gallery size, pair construction, distractors, per-query margins, and
    the absence of GPS labels are disclosed. These changes improve
    reproducibility but do not turn the proxy into a geographic benchmark.
\end{itemize}

\subsection*{Public Dataset Decision}
The primary E1 candidate is Mapillary Street-Level Sequences (MSLS). Its
official release describes 1.6 million street-level images and provides raw
longitude/latitude, capture time, sequence IDs, view direction, unique place
clusters, and standardized cross-condition subtasks. The official release and
metadata are available at
\url{https://github.com/mapillary/mapillary_sls} and
\url{https://www.mapillary.com/dataset/places}.

Oxford RobotCar is retained as a fallback because its official release has more
than 100 repetitions of a route over more than one year, GPS/INS ground truth,
and changes in weather, traffic, lighting, construction, and season. It
requires registration and is licensed for non-commercial academic use:
\url{https://robotcar-dataset.robots.ox.ac.uk/}.

The primary E5 candidate is KITTI-360. The official release contains over
320,000 images, accurate geolocation, an IMU/GPS system, continuous vehicle
poses, and 2D semantic and instance labels. Its download requires registration
and an intended-use declaration under CC BY-NC-SA 3.0:
\url{https://www.cvlibs.net/datasets/kitti-360/}.

Kaggle mirrors are not treated as authoritative. They may be used only if the
downloaded files, metadata, checksums, and license terms are verified against
the official release. A mirror that omits GPS, sequence, condition, or label
metadata cannot pass the scientific-evidence gate.

The targeted Kaggle audit found one potentially useful fallback mirror,
\url{https://www.kaggle.com/datasets/creatorofuniverses/oxfordrobotcar-iprofi-hack-23},
which describes a pre-processed Oxford RobotCar place-recognition subset and
claims GPS/INS coverage. It remains a convenience mirror rather than the
source of record because its file list and preprocessing must be compared with
the registered Oxford release. The Kaggle
\url{https://www.kaggle.com/datasets/greatgamedota/kitti360-3d-semantics}
entry is not currently acceptable for E5: its card describes fused labelled
3D point clouds and reports an unknown license, without establishing the
RGB--pose--2D-mask topology required by the validator. Mapillary Vistas
mirrors are also unsuitable for E1 because Vistas is a segmentation collection,
not the MSLS place/sequence benchmark. These mirrors may support smoke or
utility preparation, but none may supply paper-facing E1/E5 numbers without
the official-source verification gate.

\subsection*{Implementation and Paper-Writeback Plan}
\begin{enumerate}
    \item Keep the current monitoring proxy as the reproducible engineering
    benchmark and do not relabel its synthetic pairs as geographic places.
    \item Build an MSLS JSONL manifest from official query/database metadata,
    preserving the official unique-cluster place label and recording city,
    condition,
    GPS, sequence, and capture-time fields.
    \item Build a KITTI-360 sequence-held-out manifest that links images,
    semantic masks, poses, and pose-derived place cells. Use tiled occlusion of
    the query image to create the independent VPR attribution reference.
    \item Run local CUDA smoke tests first. A real run is eligible for paper
    writeback only after file-existence, label, disjointness, condition,
    non-constant-map, output-schema, and checksum gates pass.
    \item If registration, data access, checkpoint quality, or remote GPU
    connectivity remains unavailable, update the paper with the concrete
    limitation and dataset plan, but do not insert placeholder results.
\end{enumerate}

\subsection*{Required Manuscript Changes After Valid Runs}
The main paper should add the approved E1 protocol, true place-level retrieval
metrics, condition-stratified results, and a clear separation between the
proxy and geographic benchmarks. The appendix should add the MSLS manifest
schema, KITTI-360 attribution protocol, map-validation metrics, the detector
mAP table, margin subgroup analysis, and the retrieval case-study figure.
Claims about the learned unary predictor must remain limited to provenance and
attribution consistency until an independently labelled sensitivity target is
available.

\textbf{Disposition:} E1 and E5 are blocked until public data registration or
download and a usable checkpoint/remote run are available. E2--E4 and
E6--E7 remain actionable. No new paper number is approved from a smoke test or an
incomplete remote run.
